# Session reuse: development execution erratum

This is a new execution registration, before its model calls. It preserves the
original source truth and all quality criteria; it changes runner session
lifecycle and resource allowance. The original execution, its frozen inputs,
raw receipts, complete first pass and incomplete second preparation remain at
../selector-qualification/ unchanged.

## Why an erratum is necessary

The original first capture passed all eight arm trials and independent probes.
It required 281.997 seconds, including 97.814 seconds in observed agent phases;
the remaining time includes formation, fresh sessions and fixed probes. The
stricter 300-second whole-workflow stop left 17.9 seconds for a second capture,
which stopped during preparation. No completed second-capture agent trial
exists. The original wording also did not fund its potential 16 x 25 seconds
of agent phases. That execution cannot establish two-repeat qualification.

The runner repair retains the already-seeded fresh public MCP session for the
same trial's read. It reduces repeated startup without sharing trial stores,
histories, tool choices, independent probes or model responses. The public
formation and read boundaries remain real. The repair has its own public
regressions and its final evaluator binary is hash-pinned before execution.

## Exact scope and resource allowance

The same four development tasks, sources, answers and selectors are reused.
They were exposed by the earlier execution. Two newly executed captures are
independent process/store executions, not independent source-confirmation or
held-out families. This result can describe this exact repaired development
workflow; it cannot estimate population reliability or a memory treatment
effect. It does not reopen stopped C1, qualify C2, or constitute a blinded study.

Both arms use the same immutable native Apple product, explicit regex NER,
disabled embeddings and evidence stage. The model selects its actual query,
temporal selectors and tool call through the existing Rust public recall runner.
There is no fixed request substitution or supplied final answer. The independent
fixed probe remains separate. Dahlia's pre-ingestion probe uses revision zero;
the actual agent must request the registered known_at and return no forbidden
current source. No invented returned-known_at attestation is claimed.

Resource allowance is 600 seconds for the entire two-capture workflow, including
formation and probes; each agent phase retains the original 25-second acceptance budget.
With 16 scheduled arm trials, accepted agent phases sum to at most 400 seconds by arithmetic. This is
not an in-flight interruption guarantee: a blocking MCP call has a separate
transport ceiling and can return after the agent deadline. Both-arm acceptance
explicitly rejects even a Completed receipt with wall_time_ms above 25000,
turns_used above 3, or output_tokens above 384. Transport cancellation remains
separate technical debt; only the 600-second whole-workflow termination is an
execution hard bound. This registration does not claim a 300-second aggregate model-work
guarantee. Each trial retains one tool call, three turns, 384 generated tokens,
4096 context tokens, temperature zero and thinking disabled. Direct numeric
loopback MLX only; no remote model, download or LM Studio runtime. No exposed
case tuning or extra model retry is allowed after a failed gate.

## Unchanged gates and stop rule

Each capture must cover all four families in each product arm independently:
4/4 exact answers/citations, 4/4 direct agent evidence outcomes, 4/4 independent
probes, zero hard violations and zero agent resource exits. Current, valid_at,
known_revision checkpoint and pre-ingestion known_at contracts remain identical.
All ten effective selector comparisons must pass; requested/returned valid time
and the registered revision cutoff must match. Require one unique successful
observed public read and a nonblank actual query, linked to its scored read by
query/non-query argument and full raw-call hashes.

Run capture 02 only after capture 01 passes every gate for both arms. Eligibility
requires both complete captures. Stop on a failed gate or the global deadline;
keep all attempted work, failures and missing scheduled outcomes. Never turn
an incomplete repeat into an eligible result or a model-quality failure.

The reusable v3 auditor uses explicit checks that survive Python optimization.
The frozen historical v1 auditor is not used for acceptance. The Rust two-capture
qualifier and supplementary both-arm v3 audit are both required; candidate-only
Rust eligibility is insufficient if the other arm fails. Final plan, criterion,
source, runtime and active grader hashes are frozen before any new model call.
