## Execution rules

Every production behavior change follows an observed behavioral RED, minimal implementation, GREEN, then the relevant suite. Controlled providers establish ordering/faults only; their results are never native quality scores. Sources, queries, expected evidence and prohibited evidence are declared before retrieval. Corpus/model bytes and runtime identities are pinned. Unknown IDs, unavailable providers, mismatched identities, missing/extra cases and non-finite evidence fail closed. Existing failed runs remain visible. The TDD record is `work/evals/tdd-ledger.jsonl`.

## Unfinished acceptance work

The native trace separates missing candidates from candidates the reranker scores below zero. Treat these as different defects. First add a failure-first integration scenario using complete, source-grounded conversation turns and the production ingest/extract/index/read path. Assert that each required turn reaches candidate scoring before tuning its rank. Do the same for the two independent HTTP warning notes and for bounded multi-speaker conversation evidence; keep five-item response budgets, source ACLs, temporal cutoffs and negative project membership unchanged. Any conversational neighborhood must use explicit persisted source grouping/order or a documented ingestion contract, not parse LoCoMo-shaped IDs or inject gold labels into retrieval. Test out-of-group, denied, historical and conflicting adjacent turns as negative controls.

Then evaluate relevance with a source-reviewed development set separate from the 37 acceptance cases. Compare candidate recall, per-case precision and prohibited evidence against the retained r42 baseline; reject a change that trades a single extra passing case for worse precision or prohibited-free rate. Controlled-provider tests prove ordering and fault behavior only. A valid final native run must contain exactly the expected 37 outcomes, zero invalid outcomes, unchanged hashes/labels/queries, and all six 1.0 floors. The PR and release profiles must also pass on their tracked budgets. Until that happens, this plan remains incomplete even if engineering tests, Clippy and code review pass.

## Review Focus

- Qualified reference conjunction/disjunction, scope conflicts and explicit negative project membership; unrelated numeric/URL mentions must not justify a result.
- Bare multiword entities versus short attribute questions and broad-prefix attribute questions; resolved entity identity must support the requested information.
- Candidate ordering/availability with a small response budget, ANN ties, all retrieval channels, temporal windows and fallback competition; controlled tests must actually detect the original defect.
- Correct E5 purpose and raw query preservation across foreground/background paths; vector compatibility must change with the input contract.
- XLM-R model compatibility, pair truncation, malformed/missing/non-finite reranking evidence, optional configuration, inference failure and bounded runtime/memory. A relative ranking model must not be presented as a calibrated absolute relevance probability.
- Reference time versus an event date mentioned inside content; valid time versus transaction time; no fixture backdating or future/denied evidence leaking through fallback, provenance, reconciliation or caches.
- Exact source lineage for short factual turns, mixed question/statement turns and source episodes; factual content must not be manufactured from gold answers.
- Corpus usefulness labels and required groups must be source-grounded and independent of predictions. Full sessions are retained, minimal upstream answer citations are not a complete relevance oracle, and the subset is never an official benchmark score.
- Coverage and baseline comparability across model bytes, model/input/extractor/index/corpus identities; missing data/models, extra/duplicate/missing cases and incompatible baselines must be visible failures.
