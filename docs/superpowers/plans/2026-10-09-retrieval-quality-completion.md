## Execution rules

Every production behavior change follows an observed behavioral RED, minimal implementation, GREEN, then the relevant suite. Controlled providers establish ordering/faults only; their results are never native quality scores. Sources, queries, expected evidence and prohibited evidence are declared before retrieval. Corpus/model bytes and runtime identities are pinned. Unknown IDs, unavailable providers, mismatched identities, missing/extra cases and non-finite evidence fail closed. ## Acceptance work completed

The production path now persists source group and turn order as explicit episode context, and retrieval expands only eligible same-source, same-speaker adjacent question/answer evidence. Production ingest, extraction, storage, and assembly integration tests cover bounded neighborhoods, independent streams, denied and historical turns, conflicting speakers, negative project membership, and query-related antecedents. No retrieval code parses benchmark-shaped IDs or receives gold labels.

The independent source-reviewed relevance development set remains separate from the 37 acceptance cases. The mMARCO and Qwen operating-point experiments were evaluated against that set and the untouched native acceptance cases; operating points that worsened precision or prohibited evidence were rejected. No acceptance labels, queries, six 1.0 hard floors, or response budgets were weakened to achieve the final result.

The final failure-first regressions C58–C73 cover title-case search phrases misread as speakers, source-question subject and modifier matching, OR-reference alternatives, typed programming-language and owned-pet answer slots, bounded same-speaker source recovery, unknown language values/relations, and explicit pet ownership. Subject inference requires an explicit question/request frame before a capitalized candidate can be treated as a person. Typed source answers must match the requested relation and slot; unknown values remain unresolved instead of becoming hard contradictions. Pet attribution must match the named query subject or the source speaker. Source-neighborhood recovery preserves source, speaker, reference, and radius constraints. The true embedded FTS regression passes against the production database path.

## Review Focus

- Qualified reference conjunction/disjunction, scope conflicts and explicit negative project membership; unrelated numeric/URL mentions must not justify a result.
- Bare multiword entities versus short attribute questions and broad-prefix attribute questions; resolved entity identity must support the requested information.
- Candidate ordering/availability with a small response budget, ANN ties, all retrieval channels, temporal windows and fallback competition; controlled tests must actually detect the original defect.
- Correct E5 purpose and raw query preservation across foreground/background paths; vector compatibility must change with the input contract.
- XLM-R model compatibility, pair truncation, malformed/missing/non-finite reranking evidence, optional configuration, inference failure and bounded runtime/memory. A relative ranking model must not be presented as a calibrated absolute relevance probability.
- Reference time versus an event date mentioned inside content; valid time versus transaction time; no fixture backdating or future/denied evidence leaking through fallback, provenance, reconciliation or caches.
- Exact source lineage for short factual turns, mixed question/statement turns and source episodes; factual content must not be manufactured from gold answers.
- Corpus usefulness labels and required groups must be source-grounded and independent of predictions. Full sessions are retained, minimal upstream answer citations are not a complete relevance oracle, and the subset is never an official benchmark score.
- Coverage and baseline comparability across model bytes, model/input/extractor/index/corpus identities; missing data/models, extra/duplicate/missing cases and incompatible baselines must be visible failures.
