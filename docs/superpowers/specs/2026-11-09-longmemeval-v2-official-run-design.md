# LongMemEval-V2 official text-capable evaluation

- **Date:** 2026-11-09
- **Status:** Revised proposal; no benchmark score claimed
- **Baseline inspected:** `3622ceb3` (`v1.38.0`)
- **Scope:** Official upstream harness, pinned dataset and a real memory-mcp adapter

## Why this is a separate spec

[LongMemEval-V2](https://arxiv.org/abs/2605.12493) evaluates memory from ordered browser-agent trajectories with a bounded context passed to a fixed reader. It has 451 curated questions across five abilities and two domains, with text and image evidence. The paper's 72.5% AgentRunbook-C result and 48.5% RAG comparison are for its own protocol and cohort; a text-only subset here cannot be ranked against them. This work needs an upstream runner, data, reader/judge, cost and modality contract separate from the internal [decision-quality evaluation](2026-11-09-decision-grounded-memory-quality-design.md). The [agent-task evaluation contract](2026-11-09-agent-memory-outcome-evaluation-design.md) is also separate: the official fixed-reader score is evidence about memory-assisted answering, not how easily an agent uses MCP tools.

## Approaches and decision

| Approach | Trade-off | Decision |
| --- | --- | --- |
| Treat smoke or a handpicked null-image sample as a score | Cheap, but misses official registry/lifecycle failures and can include screenshot-dependent answers. | Reject as evidence. |
| Run the repinned official harness on an adjudicated text-capable Small cohort | Requires per-case modality work, reader/judge resources and a robust adapter; produces a reproducible result with honest coverage. | **Choose.** |
| Run full multimodal Small or Medium now | Better external coverage, but current product has no image representation and Medium multiplies ingest/capacity costs. | Defer to a separate capability decision. |

The goal is a faithful, failure-accounted baseline, not a headline comparison to published full-tier systems. Anti-goals are gold-label leakage, hidden truncation, scoring failed cases as empty context and unreported external data egress. The builder chooses the adapter transport and storage reset mechanism subject to the contracts below.

## Run contract

### 1. Upstream and metadata boundary

Pin the exact upstream commit with the metadata-leakage fix, dataset revision and content hashes. Keep the upstream checkout immutable; use a documented bootstrap/overlay to register `memory_mcp` in the upstream Python registry without editing the pinned source in place. Exercise the **actual** official `evaluation/harness.py` path from config through backend construction, insert, query, reader, judge and artifact output. Test that `query` sees only question text and optional image plus the permitted random invocation ID, and that neither gold answer, **private question ID/raw question record**, question type nor evaluation function reaches any adapter-visible hook or the stored memory. Trajectory and state IDs carried by the legitimate `insert` source are allowed and needed for provenance. The harness may keep private metadata for scoring; it must not pass it to memory. A register-decorator unit test alone is insufficient.

Record the reader/judge models, versions, prompts, decoding parameters, context cap, retries, timeouts, judge calibration and endpoint behavior. The official harness reports answer accuracy and query latency under that configuration when it completes. Store case-level outputs, errors and any reader/judge variability. No result is “official” if a local wrapper changes prompts, scoring or question selection after inspecting **model-generated answers or scores**. Gold answers may be used solely by blinded modality adjudicators before the cohort is frozen.

### 2. Cohort and modality

Choose a deterministic **text-capable subset of Small** before evaluating. A null question image is necessary but insufficient: every trajectory state may have a screenshot, and the pinned schema supplies no per-question evidence or modality label. To claim text sufficiency, adjudicate **every included question** against the source trajectories and reference answer, citing decisive accessible-tree/action/thought state spans; resolve adjudicator disagreement and mark negative-premise or ambiguous cases unresolved when text cannot establish the answer. Adjudicators may see gold answers to locate evidence but are blind to memory-system outputs and scores. Freeze labels, evidence-span IDs, exclusions and selection rules before any product scoring. A broad null-image filter with only a small spot audit is an exploratory cohort, not a verified text-capable one. Report full Small denominator, included/excluded counts by domain and ability, and reason codes; never call the subset “full Small” or “LongMemEval-V2 score” without qualification.

Preserve complete ordered text observations, actions, thoughts, goal and outcome with stable trajectory/state IDs. A screenshot pathname is not visual evidence. Preflight the pinned dataset's maximum serialized trajectory and extracted text against OS argument, product request, parser, extraction and provider limits. Do not silently truncate. If one-argument transport is too small, prefer a long-lived protocol; chunking must reassemble the same logical trajectory before memory formation or explicitly declare a new, versioned memory method when it changes extraction semantics. Preserve ordered lineage and test a real longest-case trajectory; fail visibly if a chunk cannot be processed. The adapter rejects image questions until image ingestion/retrieval/reader representation is designed and tested. Return a list accepted by the official harness: each present text item is nonempty, while a successful no-hit query may return `[]` and must still be scored. A retrieval error is a distinct, unscored failure, never converted to `[]`. Keep stable source mapping in a sidecar trace; do not leak gold fields into context.

### 3. Lifecycle, time and cost

The pinned Small schema shares one ordered 100-trajectory haystack across questions within each domain. Confirm how the official harness constructs and resumes that shared memory and whether it calls `save_memory`/`load_memory`; implement hooks or prove the selected path never calls them. Each independently built domain/haystack gets an isolated durable store or a proven reset. Within one haystack, repeated trajectory IDs are idempotent, stable across retry and process restart, and insertion follows official order. A failed ingest/extract affects every question dependent on that build; it is not an empty-memory success. Current product reads update fact access counters, which influence later ranking. Define this backend's query state policy explicitly: for a read-only comparison, disable such writes through a narrow eval seam or restore the same post-build snapshot per question, and verify that reversing query order leaves each result unchanged. If query-time learning is deliberately enabled, version and report that different policy and fixed order; do not describe its cases as independent.

The dataset has **no event timestamps**. Map trajectory order to a documented fixed, monotonic surrogate only if the product requires timestamps; never interpret it as actual event/validity time. All product-created timestamps, including extracted facts, relations and lifecycle events, must remain visible in the query snapshot. The current adapter's wall-clock `t_ref` and omitted `as_of` are uncontrolled. Before a comparative run, either inject one fixed run clock through a narrow evaluation seam for all writes/reads, or demonstrate through a two-date test that clock drift cannot change selected context or answers. Do not set a historical `as_of` earlier than internally generated `t_ingested`, which would hide valid evidence. If the clock cannot be controlled, report timing as a limitation and do not claim deterministic replay. This benchmark does not test independent `valid_at`/`known_at`; use the internal eval for that.

Benchmark overhead is part of the method. The current per-operation CLI subprocess can dominate 100 trajectories per Small haystack. A long-lived public server or batch adapter is allowed if it preserves normal `ingest → extract → assemble_context` behavior and does not seed gold facts or read tables directly. Measure memory formation time/calls, query time, reader/judge time, tokens, peak storage/RSS and monetary cost separately. A faster adapter is a new versioned run series. The [pinned official harness](https://github.com/xiaowu0162/LongMemEval-V2/blob/ef67f10aacd9080c75aeb2dd527a0af25dc26f1b/evaluation/harness.py) aborts on shared-memory insert errors and rethrows prompt-build errors. An external supervisor must record attempted/affected case IDs, exact failed step and retry state without modifying evaluator code or converting failure into empty context.

### 4. Run profile, denominator and publication

Freeze a machine-checkable profile: upstream/dataset hashes, product/adapter commits and features, cohort manifest, source serialization and input-size preflight, identity and clock rules, reader/judge **and extraction/embedding/reranking provider** identities, hardware class, context limit, timeout/retry policy, seeds, endpoint/egress approvals and hard cost/runtime stop. Launch with a hermetic allowlisted environment and dedicated store/config; the current adapter's inherited production environment is not acceptable for a scored run. Keep secrets and raw sensitive dataset material out of public artifacts. The official full frozen text cohort is the acceptance run; smoke and pilot are labelled as such. Keep two explicitly named results: the **unaltered official harness metric** on cases it actually scored **if the harness emitted it** (`unavailable` on an abort), and a **failure-inclusive coverage/success accounting** over every selected case. Never label the second, or any supervisor-reconstructed/merged aggregate, as the upstream metric. Predeclare a bounded supervisor rerun or partition policy that preserves the same cohort and haystack; map a failed shared-haystack build to every affected case, and keep those cases unscored by the official harness rather than scoring fabricated empty context. Classify product, reader, judge and timeout failures. Publish per-ability/domain results only with denominators and uncertainty. Recompute an available official aggregate independently from native case artifacts. A same-pin rerun must reproduce case IDs and deterministic memory inputs; model variance is reported, not concealed.

Any run that sends dataset-derived content or queries to external reader, judge, extraction, embedding or reranking endpoints, or incurs paid API charges, needs operator authorization for exact destinations and hard limits. Local-only integration tests can proceed. This document does not authorize an external run or claim an external benchmark result.

## Acceptance sequence

1. Verify the repinned upstream commit and dataset hashes. Demonstrate no backend-visible private metadata on the actual official harness path.
2. Import/register the adapter and run one selected question through the genuine harness. Exercise saved/resumed memory if the chosen path uses it.
3. Adjudicate and freeze per-case text evidence. Test ordering, identity, shared-haystack isolation, query-order effects, failure handling, context-item validity and clock behavior against the real product interface.
4. Pilot enough cases to estimate runtime, spend and bottlenecks; fix interface issues without changing gold-based selection. Freeze the run profile.
5. Run the full selected cohort, publish official scored-case metrics alongside failure-inclusive coverage and case-level receipts, and only then consider before/after comparisons of memory-quality changes. A run with unresolved affected cases does not clear the complete-baseline gate.
6. **Only when claiming a LongMemEval-V2 improvement**, run the same frozen official cohort on incumbent and candidate with matched reader/judge settings, report paired case differences and cost, and publish the independent [local agent-task result](2026-11-09-agent-memory-outcome-evaluation-design.md) if also claiming agent usability. The official run is supplementary to the ordinary local quality release gate; lack of external-run authorization blocks a V2 claim, not unrelated local changes. An improvement in the official score alone does not establish easier agent tool use; a local agent-task gain does not alter the official upstream score.

No production code, pin or external benchmark run is changed by this specification.
