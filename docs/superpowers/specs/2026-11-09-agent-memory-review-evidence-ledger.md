## November 20 investment decision

Start with a deterministic evaluation extension. Admit a product experiment only after an incumbent failure on a representative development case and freeze an independent holdout before tuning. No November proposal has a measured candidate gain. The release artifact for this exact commit reports **154/154** release cases and **61/61** separate response-size cases. The artifact contains release run `run-1795187680` and response-size run `run-1795187711`. Within release, retrieval-quality passed **37/37** with all six scores at 1.0, covering 32 answerable cases, five unknown cases and 46 required evidence groups. These are established regression floors. They leave no headroom for a positive delta on these six metrics in this corpus. Preserve them and add independently sourced histories for the target decisions. The earlier v1.39.0 retrieval comparison lacked a configured embedder. ## First-principles filter

For each idea ask: Which user decision improves? What evidence is available at write/read time? Which principal may authorize the action? What failure is observable? Can the behavior be tested on held-out, replayable cases without leaking the answer? What does it cost in latency, storage, model calls and operational complexity? Prefer an independent experiment where the claimed effect is uncertain. Accepted ADRs describe current architecture but may be revised for a measured benefit; a frozen tool count or current implementation alone is not a reason to reject a better interface.

## Corrections to the review's quantitative framing

- [SodaMem](https://arxiv.org/abs/2608.08055) reports 464/500 (92.8%) LongMemEval-S as best of three and a 90.6% median. Its reader and judge use the same model; quoted query cost excludes ingestion/judging. Cross-paper scores are not one common protocol.
- [Complementary Curation and Consolidation](https://arxiv.org/abs/2610.39790) supports dual episodic/relational representation. Its LoCoMo consolidation ablation is about 0.896 versus 0.902 without consolidation under a reported setting, alongside compression; it is not evidence for an accuracy boost.
- [agentmemory v0.9.31](https://github.com/rohitg00/agentmemory/releases/tag/v0.9.31) reports +18.94 percentage points strict recall-all@5 on inspected development data, with 92 recovered and 3 regressed cases; it is not held-out answer accuracy. Its skip-unchanged processing is an operational optimization to examine only after measuring duplicate work locally.
- [MentisDB 0.12.1](https://github.com/CloudLLM-ai/mentisdb/releases/tag/0.12.1.58) reports 23,657 → 5,948 **characters** for one generated search workload, not a universal 75% token saving. Its live-result refill has a documented cap and can still return a short page.
- The [memory-security survey](https://arxiv.org/abs/2604.16548) covers write, store, retrieve, execute, share and forget. Source-authority hardening alone does not establish full confidentiality, poisoning resistance or verified erasure.

## Dependencies and unresolved checks

The [agent-memory survey](https://arxiv.org/abs/2602.06052) supplies a useful taxonomy of working, episodic, semantic and procedural memory, but its taxonomy is not an ablation showing which mechanism this server should add. The ingestion authority change can be designed independently. The internal quality experiment needs a fixed reader, source-anchored extraction quality, server-owned transaction time and independent valid/known-time support before historical claims. The external benchmark needs a secure upstream pin, real adapter registration/persistence and modality selection; it does **not** validate real-world temporal timestamps because the dataset lacks them. The tracked [extract-quality proposal](2026-11-02-extract-quality-and-cost.md) is a possible companion, not an implemented prerequisite. No benchmark score, bug exploit, security guarantee or production policy improvement is claimed by these documents.

All proposed improvements share the [agent-memory outcome and usability evaluation contract](2026-11-09-agent-memory-outcome-evaluation-design.md). It adds a paired, held-out, real agent/tool loop to the local eval-harness and defines promotion gates for task success, evidence support, interaction effort, reliability and cost. Existing lexical/context-hit suites and a future official LongMemEval-V2 score cannot by themselves establish that agents complete more work or find the MCP interface easier to use. The contract is a falsifiable release condition, not an advance promise that every mechanism will improve both axes.

Anthropic's [“The components of agent memory”](https://www.anthropic.com/research/components-of-agent-memory) appeared after the review's source set. The [applicability addendum](2026-11-10-anthropic-agent-memory-applicability.md) separates its model-specific observations from transferable hypotheses: verified feedback loops, source-grounded offline repair, and a bounded navigation layer combined with source search. It adds sequential-learning and total-cost experiments. Its Pokémon comparison is cross-model and one-run-per-model; its wiki results come from small, internal question sets, so neither justifies an automatic write/forget rule or a universal wiki rollout.
