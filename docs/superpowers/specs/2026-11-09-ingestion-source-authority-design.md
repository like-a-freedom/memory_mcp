# Explicit ingestion authority and safe evidence handling

> **Status as of 2026-11-24.** The common ingest path treats content literally. Operators have explicit file and URL imports. Public stdio and HTTP tests cover literal file/URL text, credential refusal and redacted diagnostics. Operator and watcher tests cover the bounded file root, URL redirect refusal and stable retry. The corrected deterministic v4 profile improved from 3/4 to 4/4 primary cases across repeated captures and retains a 3/4 temporal subscore. One exact Codex workflow passed a four-family synthetic screen at 4/4 per arm, with operator setup measured separately. Legitimate-workflow non-inferiority and total user effort remain open. See [corrected v4](../../../evals/paired/source-authority-v4-2026-11-22/README.md), [qualification](../../../evals/paired/source-authority-codex-gpt62-sol-qualification-2026-11-24/runs/run-02/report.md) and [follow-up tasks](2026-11-24-agent-memory-follow-up-design.md). Query analytics are separately opt-in and can store raw queries under their retention policy.

> **Post-capture audit — 2026-11-23:** The current Codex 16-family screen is recorded in the [run report](../../../evals/paired/source-authority-current-codex-qualification-2026-11-23/runs/run-01/report.md). It failed the preregistered continuation gate (8/16 incumbent versus 15/16 candidate; independent probes 16/16 each; zero hard violations/budget exceedances), so the reserved repeat was not run. A review of the exact prompt against the contract found the incumbent source-file tasks told the agent to pass a relative path as `ingest.content`; MCP `content` is literal and only the explicit operator CLI import reads files. The incumbent 0/8 source-file result therefore reflects an unsupported benchmark path and cannot establish a memory recall defect. Candidate operator-import source-file cases scored 8/8, but this is a small synthetic workflow signal, not agent usability, non-inferiority or memory benefit. Keep legitimate-workflow acceptance open; a replacement comparison must use a supported incumbent input path, disjoint cases and a predeclared gate. No MCP import tool is authorized by this result; the existing tool surface remains frozen pending an ADR and explicit product decision.

## Memory-quality acceptance on v1.41.0

The shared content preparation path can still replace a caller's literal content and source identity during import. Measure the effect in disposable stores with inert, controlled source adapters. Ingest a literal reference, remember another ordinary fact, then ask for the original reference in a later session. The oracle checks the exact authorized source binding and literal evidence returned under a fixed budget. Score the ordinary fact independently and include unknown-reference controls. A substituted document, lost literal or unsupported answer fails that case. Apply the [deterministic memory-quality gate](2026-11-09-agent-memory-outcome-evaluation-design.md#deterministic-memory-quality-gate) and legitimate-workflow migration checks before counting this change toward the memory program. Diagnostic redaction can proceed on its own security merits and carries no assumed retrieval benefit.

## Problem and evidence

`ingest.content` currently doubles as memory data and an instruction to read a server file, directory, or URL. [`prepare_ingest_request`](../../../crates/memory-mcp/src/memory/content_extraction.rs) checks path existence, reads paths, and fetches HTTP(S) before the request is validated. The HTTP fetcher already validates public DNS, pins addresses, disables proxies/redirects, and bounds response size and time; these controls do not authorize the fetch itself. [Inline `extract`](../../../crates/memory-mcp/src/tools/extract.rs) also creates an episode via the same ingestion capability. A local stdio MCP caller is still an agent-controlled caller: a prompt-injected agent can submit a path it could not otherwise read through its tools. A trusted operator and an agent running on the operator's machine are different principals.

Raw `source_id` crosses two logging layers: [`tools::ingest`](../../../crates/memory-mcp/src/tools/ingest.rs) emits it at start/success/error, and [`IngestionService`](../../../crates/memory-mcp/src/memory/ingestion.rs) logs it by default. Parser/fetch errors and invalid `t_ref` can echo raw input. [`tools::assemble_context`](../../../crates/memory-mcp/src/tools/assemble_context.rs) logs the raw query. Reviewing only the storage seam would leave the disclosure path open. The [agent-memory security survey](https://arxiv.org/abs/2604.16548) distinguishes write authority, provenance, scoped retrieval and verified forgetting; this design addresses write authority and diagnostic leakage, not all four.

[cognee v1.6.7](https://github.com/topoteretes/cognee/releases/tag/v1.6.7) is supporting prior art for refusing unsafe path/connection inputs by default. Its exact policy is not evidence that our current code has an exploitable SSRF. [OWASP's SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) supports destination validation for any authorized URL import.

## Approaches and decision

| Approach | Trade-off | Decision |
| --- | --- | --- |
| Keep auto-detection with path/URL filters | Least migration, but content still selects a privileged action and every parser/fetch path needs defense. | Reject. |
| Literal agent content plus a bounded operator import route | Breaks local convenience and needs a migration, but gives the write boundary one comprehensible meaning. | **Choose.** |
| Give agents a separate import MCP tool | Could serve a future agent workflow, but requires independent authorization, user intent and an ADR. | Defer until that workflow is demonstrated. |

Success means an agent-supplied string cannot initiate an unauthorized server read, and diagnostics cannot disclose the string or its identifiers. The anti-goals are silent evidence rewriting, a superficial regex-only security claim, or a CLI flag presented as proof of human authorization. The builder chooses internal types and platform-specific safe-open mechanics within the observable contract below.

## Contract

1. **Data is never an authority token.** The `content` and `text` fields of every agent-facing MCP `ingest` and inline `extract`, local stdio or HTTP, mean literal content. Enforce this at the shared writer so lifecycle capture, control-plane upload and future entry points cannot bypass it. An existing path, `https://` URL, or connection string cannot trigger file/network I/O. `source_type`, `source_id`, `source_group`, tags, or transport headers cannot grant import rights. A literal URL may be remembered as text; it is not fetched. This intentionally breaks the current local convenience behavior.
2. **Operator imports have explicit intent and bounded authority.** The implemented local CLI provides `import file` for one file and `import url` for one URL, outside the agent-facing `content` contract. File import requires an absolute `--root` and a relative `--path`; `cap-std` opens the file relative to the root capability, rejects parent/absolute paths and symlink escapes, and enforces a 4 MiB limit. Unsupported formats fail with a generic error. Recursive directory/batch import is deliberately deferred: callers can issue one command per file, while batch limits, partial-failure reporting and atomicity lack a demonstrated workflow. The root is selected by the CLI caller, not loaded from protected operator configuration; this separates MCP data from an explicit CLI operation, but is **not** an OS identity boundary. A process or agent with shell access as the same user can invoke it. URL import validates HTTP(S), public DNS answers, and pins resolved addresses; it disables proxies and redirects and applies connect, total-time and 4 MiB response limits. URL userinfo and credential-like query keys are refused before DNS/request. There is no host allowlist configuration today. No request-controlled `is_trusted` flag. A new MCP import tool is out of this proposal unless a demonstrated agent use case and authorization model justify an ADR; the frozen tool count is a current constraint, not an architectural proof.
3. **Watcher is a distinct authority.** The configured inbox grants only watcher-originated reads under its containment rules. Watcher-prepared text is passed as literal bytes; a snapshot whose text resembles a path/URL must not be reinterpreted by generic ingest. Provenance records the actual source kind, stable source identity, and authorized actor without treating those labels as permission.
4. **Validate and make operation boundaries explicit.** Perform access/size/shape checks before optional I/O, validate imported text and identifiers before the episode write, and make that write atomic. For `ingest → extract`, an `ingest` success means the episode is durable, not that extraction succeeded. For inline `extract(content|text)`, the episode may already be durable when extraction fails. Return a stable episode identity and a pending/retryable extraction state, never claim that derived facts exist, and define whether partial derived writes are invisible or rolled back. Retries must use the same source identity without duplicating the episode or publishing half a claim graph. Reject malformed time and identity fields without reflecting the submitted value. Distinguish refused input, failed import, and failed extraction; never report a failed import as a successful episode.
5. **Credential handling is explicit and limited.** Default agent-facing writes refuse high-confidence credentials (for example URI userinfo/password, private-key blocks, known token formats) before persistence. Apply the same check to imported content and all identifying metadata. For operator URL import, check the submitted URL before any DNS/request and check fetched text before persistence; a fetched body may arrive over the network before its content can be classified. Keep a reason code and safe correlation ID, never the matched value. Do not silently alter primary evidence or claim that heuristic detection is complete. Document false positives, and define any privileged exception only as a separate audited operator workflow with retrieval restrictions; do not add a caller-controlled bypass. This policy does not imply that all personal or confidential facts are prohibited.
6. **Diagnostics are content-safe end to end.** Tool, context, transport, parser, storage, and worker logs/errors must not serialize raw `content`, query, path, URL query/userinfo, `source_id`, `source_type`, `source_group` or caller-supplied tags without a field-specific safe encoding. The shared logger now redacts known sensitive field names at its event and rendering boundaries, but returned error messages and arbitrary caller-owned tracing subscribers remain separate surfaces that require explicit review. Use bounded operation IDs and typed reasons. Audit existing log fields and error formatting before declaring the boundary closed. This also protects identifiers that are sensitive without matching a token pattern.

## Migration and acceptance

The public `ingest` wire behavior changes: publish a migration note showing literal ingestion and explicit operator import. Keep historical stored episodes unchanged. No schema change is needed. The implementation adds the exactly pinned `cap-std = 4.0.3` dependency for root-relative file access; the user approved this dependency and lockfile update. This is the patched release for the upstream [symlink-confinement advisory](https://github.com/sunfishcode/cap-std/security/advisories/GHSA-hp8f-xmx4-4qrg) affecting cap-std through 4.0.2. Preserve deterministic episode identity, provenance, tenant isolation and bi-temporal timestamps. The composition root injects narrow source permissions; it must not give a use case the whole service container.

Acceptance is an explicit, bounded matrix across the actual writer boundaries: real stdio and HTTP MCP calls, inline `extract`, the lifecycle adapter, configured watcher snapshots, and any future control-plane writer. For each present boundary, use at least one existing path and one loopback URL; prove no unauthorized read/request and literal or safely refused behavior. The watcher may make one bounded read of its configured snapshot, but generic ingestion must not import that prepared text again. Test high-confidence credential refusal in content and identifying metadata, plus benign URL discussion to constrain false positives. Test operator file/URL imports, root/symlink/size limits, pre-network credential and DNS rejection, and redirect refusal. Inject failures before and after durable writes: verify episode identity, truthful pending/partial state, idempotent retry, and no inconsistent derived graph. Capture product logs and returned errors at real stdio and HTTP boundaries for content, path, URL, credential, source identifiers, lineage and policy tags. A source-authority security claim requires these gates plus a threat-model review; synthetic recall scores alone cannot close it.

**Current acceptance gap:** deterministic evidence now includes a same-fingerprint v4 baseline at 3/4 and final candidate at 4/4, repeated twice each; exact results, binary/config/corpus hashes and limits are in the replay archive. Real HTTP and stdio product tests cover literal file-path and loopback-URL ingest/extract/recall, prove no loopback request, refuse credential content, and inspect logs for content, identifiers, source groups and tags. The stop-hook shell script is separately tested against a capture MCP server; watcher snapshot behavior is covered at its processor boundary. A control-plane content-ingest route is absent; any future writer must delegate to the shared ingestion contract and add transport coverage. Extraction retry is covered both before fact creation and after facts have been written: the latter returns `partial`, retries with the same episode identity, and leaves the fact count unchanged. A controlled URL-redirect regression proves the target is not contacted. The common logger regression exercises nested sensitive fields in text/JSON output, free-text errors, and values before they reach a tracing subscriber; real stdio/HTTP tests cover their named production paths. The source-authority import/validation errors and operator-import CLI errors are reviewed; malformed record IDs and refused credential material are not echoed. This bounded review does not establish a guarantee for every MCP error variant or arbitrary custom tracing field: valid `NotFound` responses retain the same-caller supplied identifier under the existing response contract. Credential checks are high-confidence pattern checks, not general DLP. Legitimate-workflow non-inferiority is open: prior pilot data was underpowered and cannot support equivalence. Do not describe the proposal as fully accepted, claim broad usability gains, or call CLI imports a separate OS principal.

The [agent-task evaluation contract](2026-11-09-agent-memory-outcome-evaluation-design.md) adds a separate usability and legitimate-workflow gate in `crates/eval-harness`: an agent must still remember and later retrieve a literal URL/path, successfully complete authorized writes, understand a refused credential-bearing write and retry an extraction failure without duplicate episodes. Operator-only import is an integration/setup test, not an agent MCP action. Compare incumbent and candidate on paired multi-session tasks, measuring task success, invalid calls, repair turns, tokens and latency. Security passes only with tested unauthorized-read prevention **and** non-inferior legitimate task success within preregistered bounds; the migration must not be called more convenient solely because it reduced a class of tool calls. A breaking interface needs a versioned agent-instruction/tool-schema migration tested on both stdio and HTTP.

## Bounded threat-model review — 2026-11-22

This review checks the concrete source-authority boundaries in the current tree. It does not certify arbitrary-secret detection, operating-system isolation, or every embedding of this library in a third-party tracing stack.

| Threat | Implemented control and local evidence | Residual boundary |
| --- | --- | --- |
| Agent text is reinterpreted as a privileged path or URL read | MCP ingestion stores the submitted string literally. Real stdio and HTTP process tests ingest and recall a local path and loopback URL while proving the file contents were not substituted and the listener received no request. | A separate local CLI import is still callable by any process running as the same OS user. The caller-selected `--root` is an operation boundary, not proof of a distinct human principal. |
| Explicit file import escapes its selected root or reads an unbounded object | `cap-std 4.0.3` root-relative open, relative-path validation, symlink/traversal refusal, regular-file check, and a 4 MiB cap; `operator_import` integration cases cover the refusal paths. | The CLI caller selects the root. Recursive import is deferred; there is no directory traversal contract. |
| URL import reaches a private destination, follows a redirect, or bypasses address validation through a proxy | HTTP(S)-only, credential/query refusal before DNS, public-address validation, pinned resolved addresses, `no_proxy`, redirect policy `none`, connect/total timeouts, and a 4 MiB cap. Local tests cover loopback refusal and a controlled redirect whose target listener remains untouched. | Public servers are still untrusted content sources. This is destination control, not content sanitization or trust in fetched text. |
| Caller content, query, source metadata, credentials, or record IDs leak through service logs | Map events are sanitized before `tracing`; text/JSON renderers recursively redact known sensitive field names; foreign fields are sanitized and `rmcp` diagnostics are generic. Formatter tests and real stdio `RUST_LOG=trace`/HTTP log-file tests cover the named paths. Malformed record-ID errors retain table-prefix guidance without echoing the submitted value. | Redaction is field-name based, not arbitrary-secret DLP. Review new dynamic fields before emission. A valid-but-missing resource ID is still returned to the same caller in the MCP `NotFound` contract. A host application's independent tracing subscriber may observe native events it creates outside the service logger. |
| Search queries are silently retained by diagnostics | Diagnostic logs contain no raw query. `QUERY_LOGGING_ENABLED` defaults to false. | Explicitly enabling query analytics intentionally persists raw queries to `query_log` for the configured retention period; this requires an operator data-retention decision. |
| Watcher or lifecycle input is reinterpreted as another source read | A configured watcher snapshot can be read once by its adapter and then passes through the common literal writer. Processor tests cover a path and loopback URL in one prepared snapshot; the stop-hook script is tested against a capture MCP server. | Only the named adapters and current configuration are covered. Any new writer must reuse the contract and add a real transport regression. |

This review closes the bounded threat-model documentation task. It does not close the separate paired legitimate-workflow/non-inferiority gate, and the source-authority migration must not be described as broadly accepted or more convenient until that gate has evidence.

This specification is independent of the [memory quality](2026-11-09-decision-grounded-memory-quality-design.md) and [LongMemEval-V2](2026-11-09-longmemeval-v2-official-run-design.md) designs. Its scope excludes physical erasure, malicious content classification, and arbitrary-secret DLP; those are separate threats with different evidence and contracts.
