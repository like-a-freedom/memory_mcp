## Deterministic memory-quality gate

1. Extend the existing [native suite](../../../crates/eval-harness/src/suites/retrieval_quality.rs) and [evidence-group scorer](../../../crates/eval-harness/src/suites/retrieval_quality/scoring.rs) for retrieval cases. Add a registered suite for multi-step writes, revisions and public MCP traces where a single ranked list is insufficient. Preserve the 37-case profile and its six existing floors. Keep the new cases and expected coverage in a separately versioned profile. Run the [native profile with verified model directories](../../../evals/corpora/retrieval-quality-v1/README.md) in both arms. Record the deployed configuration as a separate arm if it differs from the native acceptance configuration.
2. Use fresh stores with the same engine/version, an ordered source bundle, fixed clocks and explicit maintenance barriers. Freeze query order, budgets, resolved model hashes, runtime, feature flags and thread/device settings. Drive the actual changed write/read path. Bind returned evidence to stable fixture source keys through native readback. Keep oracles, future events and derived gold facts outside the product. Recorded model outputs are allowed only at unchanged dependencies. If a candidate changes extraction, ranking or offline generation, exercise that component in the tested arm. Replay of cached candidate answers can verify a scorer but cannot qualify the component.
3. Give each answerable case one point only if the public result fits the fixed budget, covers at least one permitted source from **every** required group and contains no forbidden or stale evidence. Bind each key to the expected claim/version or source span where one episode contains multiple versions. On an unknown, disputed or refused case require its declared disposition and precisely its allowed evidence conditions. A missing result, timeout or unresolved binding scores zero. A missing case receipt also invalidates run coverage. Report the numerator, denominator, wins, losses and unchanged cases by stratum. Keep access, time leakage and unsupported decisions as independent hard failures.
4. Execute each arm twice from clean state. Require exact equality of per-case normalized evidence keys, rank order, dispositions and scores across repeats of that arm. Exclude opaque runtime IDs and elapsed time from equality and retain them for diagnostics. Pin resampling algorithm, seed, independent history/family units, interval level and number of draws. Repeats check reproducibility and add zero independent examples. A provider or scheduler that fails replay equality makes the comparison inconclusive.
5. Before opening the holdout, register one primary target cohort and a worthwhile absolute gain in case success from a development pilot. Require the lower bound of a paired 95% interval on candidate minus incumbent to exceed that positive margin. Apply prespecified broad-workflow and important-stratum regression budgets and all existing floors. Freeze sample size and prohibit post-hoc cohort selection. Zero applicable cases, incompatible manifests, an underpowered interval, or a ceiling result cannot qualify a feature. Run each independent mechanism against its immediate incumbent and check the complete release against the frozen starting baseline. An added suite earns acceptance through correct scoring of known failures and replay parity. Its existence earns no product gain.

The deterministic gate measures what memory returned through the public MCP interface. It runs without an agent runner or model account. Scripted traces establish that the interface permits a workflow and can count its mandatory steps. A usability claim about how often agents discover that workflow additionally requires observations from a fixed agent under the paired protocol below.

## Decision and limits of a guarantee

No design can guarantee a future empirical improvement before implementation. The enforceable guarantee is a **promotion rule**: a candidate is not described as better for agents, nor shipped on that claim, unless a preregistered, replayable comparison supports the specific claim, with safety and resource invariants intact. An inconclusive result blocks that claim. Every product candidate in this program must first pass the deterministic memory-quality gate above. Separate security or efficiency work may be justified independently. To claim that the combined program improves **both memory and agent convenience**, require separate positive gains in direct memory evidence, downstream task success, and a prespecified agent interaction measure.

This spec owns the common test method and gates. The three linked specs own their product behavior and scenario-specific acceptance. External leaderboard scores are supplementary and retain their own protocol and denominators.

## What current evidence can and cannot establish

The current [profile format](../../../crates/eval-harness/src/profile.rs) selects suites and aggregate floors/regression budgets. [Run artifacts](../../../crates/eval-harness/src/artifact.rs) fingerprint some build, model and corpus state. [End-to-end](../../../crates/eval-harness/src/suites/end_to_end.rs) ingests/extracts/assembles and checks context fragments; its historical fixture supplies `t_ingested` from the caller. [Action grounding](../../../crates/eval-harness/src/suites/action_grounding.rs) uses a hard-coded action policy and tests a context hit, not an agent choosing tools or finishing a task. [External retrieval](../../../crates/eval-harness/src/suites/external_retrieval.rs) seeds facts and computes `answer_presence_proxy_at_5`, explicitly a weak lexical diagnostic. [Response size](../../evals/README.md) measures serialization, not whether an agent uses the response correctly. These suites are useful component checks but cannot support an agent-usability or downstream-outcome claim. The proposed work adds an actual agent loop and paired comparison to `crates/eval-harness`; it does not relabel existing metrics.

[MemoryAgentBench](https://arxiv.org/html/2507.05257) tests incremental interactions across accurate retrieval, test-time learning, long-range understanding and selective forgetting. That competency coverage is useful for local scenarios, but its scores do not measure this MCP interface's ease of use. [MemBench](https://aclanthology.org/2025.findings-acl.989/) explicitly separates effectiveness, efficiency and capacity; these are distinct objectives, not a single accuracy score. [τ-bench](https://arxiv.org/html/2406.12045) demonstrates multi-turn tool/user evaluation with a final-state oracle and repeated-trial `pass^k`; its retail/airline tasks do not transfer directly to a memory server. [The Epistemics of Agent Memory](https://arxiv.org/html/2609.33013) found its internal consolidation score did not predict external transfer. These sources justify testing the **agent's downstream work** independently of memory-internal proxies. The local task set and thresholds below are design proposals, not published benchmark results.

[CL-Bench 1.0](https://continual-learning-bench.com/news/cl-bench-1-0/) explicitly scores dependent task sequences and compares stateful systems with stateless controls to distinguish learning from base ability. [Anthropic's component study](https://www.anthropic.com/research/components-of-agent-memory) uses that style of task for memory notes and reports both promising transcript-checked repair and mixed wiki value; its [local applicability analysis](2026-11-10-anthropic-agent-memory-applicability.md) sets the transfer limits. Sequential learning needs its own experiment mode because the independent-case paired protocol below would erase the very carryover being tested.

## Unit of evaluation and task corpus

An eval case is an ordered, multi-session history, an agent-visible user request and policy, an access principal, an isolated store snapshot, and a hidden oracle for the desired final answer and/or state transition. The agent uses the public MCP protocol and advertised tool schemas, not direct service methods or seeded gold facts. Store the actual tool calls, arguments after secret-safe redaction, result/error classes, pseudonymous source references, final response, resulting durable state, model usage and timings. Tool outputs, extraction and reader prompts are preserved only in access-controlled artifacts after the ingestion policy's secret handling; public aggregates contain no raw content or identifiers. The scorer and raw oracle stay isolated from the agent and memory policy: only in sequential-feedback mode may a one-way harness adapter release the **preregistered agent-visible projection of a completed task's verified outcome**, identically in every arm and only after that task is scored. Hidden evidence spans, future queries and future labels remain sealed.

Construct and independently review cases for: factual recall across sessions; a newly corrected fact versus its predecessor; late-arriving evidence with separate valid/known times; two live conflicting sources and appropriate uncertainty; a durable owner decision; a taught procedure applied later; a preference change; an archived item needed later; no-answer/abstention; denied cross-principal retrieval; and literal path/URL text. Operator-only imports are **setup/integration cases**, never agent-selected MCP actions; their result can become a later agent-visible history. Include long histories and distractors, realistic user phrasing and multiple surface forms. For action tasks, use a simulated external system with a deterministic final-state oracle; no real side effects. A case is invalid if its intended state or acceptable answer cannot be independently specified. Maintain a small public development set and a sealed, versioned holdout. Fix ambiguous cases before seeing candidate results, and replace a contaminated holdout rather than editing its gold after the fact.

The task manifest pins case IDs, histories, oracle version, **alternative sufficient sets of source evidence**, prohibited evidence, risk class, principal, allowed tools, clock/revision mapping and resource caps. In **fixed-history mode**, score direct memory quality with a separate pinned query/probe at the same principal, time and token budget in both arms, on an isolated/reset post-history snapshot; the probe must not prime the agent's subsequent run. On answerable cases, its oracle requires at least one complete sufficient set and no prohibited/stale item. On unknown or access-denied cases, the oracle requires an appropriate empty/uncertain response or policy refusal and zero forbidden disclosure; these have their own denominator and are never mislabeled as positive evidence recall. Agent-managed memory has separate write/outcome metrics and does not enter this direct fixed-history evidence comparison. Distinct tasks must be sampled as the statistical unit. Repeated model trials of one task estimate that task's reliability, not extra independent cases. Freeze strata and weights before evaluation; report each stratum and the macro average so a large easy class cannot hide temporal, conflict, security or procedural regressions.

## Paired experiment

Run **incumbent** and **candidate** on the same held-out cases with the same agent model/version, host policy, user requests, tool and context budget, reader/judge configuration, extraction/embedding provider identities, hardware class and stop conditions. Use two declared case modes: **fixed-history replay**, where the harness feeds identical ordered source events through each product's public write path and scores memory formation cost/failures separately; and **agent-managed memory**, where the agent chooses MCP writes/updates and those choices are part of task success and effort. Never pool the modes into one causal score. Isolate every case and trial in a fresh tenant/store or restored snapshot; keep intended source events and order identical in fixed-history mode. Capture a single run clock or committed revision and prevent evaluation reads from changing the next trial's heat/rank. Interleave arm order when remote models or infrastructure can drift. Record model nondeterminism and run a preregistered number of repeated trials per case; do not cherry-pick the best run. A no-memory arm and a budget-matched raw-history arm are useful diagnostics, but the promotion comparator is the incumbent product. If an interface break changes tool schemas, allow only the minimal schema/prompt migration necessary to operate that interface and publish the exact diff; a more elaborate new agent strategy is a separately named factorial arm, not a hidden product gain.

Keep ordinary-workflow regression cases separate from **new-capability cases** such as an independent historical `known_at` or owner review decision. Give both arms the identical legitimate user goal and oracle. If the incumbent lacks the capability, record its actual failure or appropriate refusal as an unsupported-task outcome; do not add a fake compatibility feature or punish a safe refusal as a safety violation. Report broad-cohort non-inferiority and new-capability gains separately. Run adversarial source-authority cases only with controlled fake file/network adapters and inert fixtures; never let the incumbent make an uncontrolled external request to establish a baseline.

Use the actual agent loop: provide MCP tool descriptions, let the agent choose calls, execute them through a thin transport adapter, return product responses, and continue until final answer, safe refusal, budget exhaustion or tool failure. The agent must have at least one opportunity to recover from a tool error within the same declared budget. A deterministic scripted runner is required for CI contract and scorer tests, but its success is **not** evidence of model-agent usability. A fixed production-like agent/reader is required for the comparative release claim. Run adapter parity tests across stdio and Streamable HTTP when the changed contract is exposed on both.

For a **sequential-feedback** experiment, keep one isolated memory state across a preregistered series of related tasks. Score each task before revealing its **oracle-verified** outcome as input to the next task; a model's own answer is not verification. Freeze task order, feedback timing/content, permitted write and offline-maintenance windows, and whether the agent or harness captures each event. Run **multiple independent held-out sequences**; repeat each whole sequence with fresh stores and fixed models. Pair incumbent and candidate on each sequence, and estimate intervals by resampling independent sequences (or shared task-template families), keeping nested rollouts together. A stateless/no-persistent-memory control estimates the benefit of having memory, but is not the comparator for a candidate-gain claim. Report per-step success and cumulative reward, harmful carryover, later correction, calls and total write + offline + read cost; never count steps or repeated rollouts in one sequence as independent samples or change a prompt/model only in the candidate arm. A completed offline pass must be available at the declared boundary or recorded as a miss/failure. Pre-register a positive candidate-versus-incumbent sequential margin and total-cost ceiling for a sequential-learning claim. This mode is separate from the independent-case promotion cohort; a benefit on one does not silently substitute for the other's gate.

Pre-register a pilot-derived smallest worthwhile improvement `δ_task > 0`, tolerable broad-cohort harm `ε_task`, and resource/interaction budgets before looking at holdout candidate outcomes. Choose sample size/repetitions to resolve those margins using baseline variance; if cost prevents this, report insufficient evidence. Use paired task-level bootstrap intervals (resampling tasks, preserving all trials within each task), and publish discordant win/loss counts. For repeated trials, report per-task success and a fixed, preregistered `pass^k` as a reliability diagnostic; `pass^k` means **all** k attempts succeed, not at least one. Do not use trial-level intervals that treat repeated attempts as independent tasks.

## Metrics and scoring

| Layer | Required measure | Interpretation and gate role |
| --- | --- | --- |
| Downstream outcome | Failure-inclusive exact task success / correct final state; source-supported answer and appropriate abstention | Primary. A timeout, invalid tool call that never recovers, model failure, or skipped case is unsuccessful, never removed from the denominator. Use deterministic oracles where possible; blinded human adjudication resolves genuinely semantic cases. |
| Memory evidence | Sufficient-evidence-set success at fixed context budget, prohibited/stale evidence rate, temporal validity, source support and conflict/unknown handling | Direct memory quality and hard safety/correctness invariants. A high lexical retrieval proxy cannot substitute for sufficient evidence or task success. |
| Agent interaction | Tool calls and repair attempts per task, invalid argument/error rate, turns to correct evidence, user clarification/handoff count, completion within fixed call/token budget | Usability indicators from real traces. Report both unconditional per-task values and values among successful tasks; the latter alone has selection bias. |
| Efficiency | Input/output tokens, wall time p50/p95, memory formation/query time, storage/RSS and estimated money per task and per success | Separate formation from query and reader/judge costs. Compare at fixed quality and fixed budgets; never claim universal token savings from response characters. |
| Reliability and coverage | Per-task repeated success, fixed `pass^k`, completed/attempted cases, error attribution | Averages alone can hide flaky agents; missing artifacts or unknown failure class fail the run integrity gate. |

For answers, grade factual correctness **and** support from evidence visible at that trial's `known_at`; an unsupported correct guess does not count as memory-grounded success. For actions, compare the simulated final state and safety policy. Unsafe execution, unauthorized source import/read, cross-principal disclosure, fabricated review decision, or a stale fact asserted as current is a hard failure even if the final prose appears correct. A safe abstention succeeds when the oracle says evidence is insufficient; a policy refusal succeeds when access is denied. Over-abstention on an answerable, authorized case fails. If an LLM judge is unavoidable for semantic equivalence, blind it to arm identity, calibrate against double-reviewed human examples, retain disagreement/appeal records, and do not let that judge alone certify a high-risk action. A reader and judge sharing a model must be disclosed and checked for correlated errors.

These are evaluation-integrity tests, not product-performance evidence.

## Promotion decision

For a **quality** change, require the lower paired interval bound for downstream task success on its target cohort to exceed preregistered `δ_task > 0`, the deterministic memory-quality gate to pass, broad ordinary-workflow success to be non-inferior within `ε_task`, and agent/resource ceilings to hold. For a **retention efficiency** claim within this program, additionally require a preregistered cost or storage gain and non-inferior task success on future queries; do not claim higher accuracy from cost alone. For an **agent interface** change, require a positive gain in a prespecified trace-based interaction measure and non-inferior task success. For **source-authority security**, require zero successful unauthorized reads in tested threat cases, legitimate-task success non-inferiority and bounded migration effort; this does not certify the absence of every possible exploit. Every category also requires zero hard temporal, support, access or safety invariant failures, valid run coverage/fingerprints and calibrated scoring. The release report gives raw rates, paired deltas/intervals, `pass^k`, every important stratum, costs and all failures, including negative results.

To claim the **combined program** improved memory metrics **and** agent convenience, require positive preregistered paired gains with lower interval bounds above `δ_memory > 0` for direct sufficient-evidence success, `δ_task > 0` for downstream task success, and `δ_interaction > 0` for one named agent interaction measure (default: fewer error/repair turns per task, with failures charged the maximum allowed turn budget so early abstention cannot appear efficient). Freeze those margins and the exact failure charge before the sealed run; choose a different interaction measure only from baseline pilot evidence and name it before holdout scoring. Other usability, cost and important-stratum measures must remain inside their non-inferiority budgets. This conjunctive claim is stronger than any single component's promotion gate.

Do not aggregate independent mechanisms into one favorable score. Compare each consequential change to its immediate incumbent and the combined release to the pre-program baseline; retain ablations so an attractive bundle cannot hide a harmful component. The decision is **promote**, **reject**, or **insufficient evidence**. A failed or incomplete external model run is not promoted by passing offline tests. Any threshold revision after seeing the holdout requires a new holdout/run version and an explicit rationale. The document and harness must preserve that audit trail.
